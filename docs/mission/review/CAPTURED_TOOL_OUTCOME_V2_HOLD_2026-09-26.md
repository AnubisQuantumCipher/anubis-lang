## Blocking finding

`observe_z3_process` permits arbitrary trailing stdout after a literal `unknown` when `has_get_model` is true (patch lines 1118–1203, projected `compiler/src/middle/mod.rs:22047–22149`). It checks an exact trailing error for `unsat`, rejects an `(error …)` after `sat`, and constrains the memory-refusal case; there is no corresponding check for `unknown`. A present fake z3 that emits:

```text
unknown
(error "sort mismatch")
```

and exits successfully becomes `Z3Observation::Answer("unknown")`. The primary fallback then calls `classify_obligation_z3_answer`, whose literal `unknown` arm returns `IssuedSolverOutcome::Undecided` (patch around projected `middle/mod.rs:21619–21730`). More seriously, the native-primary UNSAT branch invokes `observe_z3_process(..., true)`, then `native_unsat_crosscheck` permits an `Answer("unknown")` and returns typed `Proved` on the native certificate (patch around projected `middle/mod.rs:21392–21449`). Native vacuity uses `has_get_model=false`, so its extra-response guard correctly rejects this transcript. Thus the explicit process error is hidden by the first line on the primary obligation path. This does not show an invalid native certificate, but it falsely reports a completed optional cross-check and misstates the z3 failure.

Add a deterministic fake-z3 control through `z3_process_at` that emits the transcript above with success status and expects `Z3Observation::Failure { failure: SolverToolFailure::RejectedQuery, .. }` or an explicitly justified `MalformedResponse`. On a native-decided UNSAT obligation, the captured producer should then yield `CapturedSafeCheckFailure::ToolFailure`, not a successful native result. In the z3-only fallback it should also remain a typed tool failure, rather than `SolverRefused` as `Undecided`. Define the exact allowed secondary transcript for a real `unknown` plus unconditional `(get-model)` using a source-bound z3 observation; any unrecognized trailing error must not inherit `Undecided`.

## Findings closed from v1, subject to execution

- `z3_process_at` distinguishes a missing executable from a found tool whose spawn/write/wait fails. Native-primary UNSAT/SAT and native-vacuity use `observe_z3_process` and propagate `Failure` rather than treating it as absence (patch lines 311–428, 470–620, 1001–1210). Native-only authority remains available only for `Absent`.
- Native vacuity now classifies unrecognized first lines such as `maybe` as `MalformedResponse`; its prior silent fallthrough is removed (patch lines 364–425). The added fake-z3 control reaches the vacuity transfer function, although it does not invoke `check_and_lower_safe_rust` end to end.
- The primary fallback observes process exit status before mapping an answer to `Proved`. The saved probe records `unsat`, then `(error "line 6 column 10: model is not available")`, exit `1`, with empty stderr; `expected_post_unsat_model_error` recognizes that shape. A different nonzero exit becomes `NonzeroExit` (patch lines 1068–1201). This is an observed local z3 behavior, not a universal solver-protocol theorem.
- The runner takes and drops stdin, then calls `wait_with_output` even after an ordinary write error; it prioritizes an explicit first-line query rejection over a broken pipe (patch lines 1060–1120). The fake partial-write test injects `write_error` into a completed result, so it tests the classifier priority, not an actual OS partial-write or child lifecycle.
- Captured inventory now has outcome-specific wire status sets: `Disproved`, `ContradictoryPremises` and `Unencoded` require `FAIL`; `NoObligations` and `Proved` require `PASS`; `Undecided` and `ToolFailure` permit the declared refusal statuses (patch lines 1656–1698). The v1 `Disproved` plus wire `UNKNOWN` gap is closed. The public `SolverCheck` shape remains unchanged; `CapturedSafeCheckFailure` remains crate-private.

## Limits and integration risk

`z3_process_at` still returns `Wait` on a `wait_with_output` OS error without an explicit kill/reap recovery path. That rare path has no witness here; normal completion and the write-error path do call `wait_with_output`. The new fake solver tests use an explicit executable path, avoiding a shared `PATH` mutation, but the static review did not run them. They do not demonstrate that the actual captured project propagates an injected process failure end to end. A real z3 positive control and same-corpus public `SolverCheck` comparison are still needed, especially because strict stderr/trailing-output rules can change prior valid or undecided rows. The legacy raw-query helper still returns `None` on a failed present process; the native raw cross-check now uses the richer observer, while fallback raw callers must remain independently checked for fail-closed behavior.
