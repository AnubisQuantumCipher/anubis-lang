The independent reviewers held the candidate for these mechanisms:

- `PcWriteScan.public_outputs` and `.unresolved` are declared `Vec<String>`
  but initialized with `BTreeSet::new()` (candidate `middle/mod.rs:28212-28217,
  :28757-28766`). Formatting is not a compile check.
- A saved lambda carries its expression but not its definition-time captures.
  `scan_lambda` looks up nested calls in call-time locals (`:28265-28295,
  :28433-28450, :28539-28565`). A later shadow of an egressing captured
  function can make the scan inspect a pure function instead. The runtime
  captures values when the closure is made (`LANGUAGE.md:296-299`).
- The direct secret-PC producer can treat an incomplete callable set as
  complete. `pc_scope_lambda_candidates_complete` ignores `FnMay.open`
  (`:28167-28175`). An `identity(lambda)` branch can be omitted by
  `multi_candidate_closures` while empty named/builtin domains misleadingly
  certify the retained pure lambda. First-class builtin effects are not
  fully summarized. A closed callable-target/effect domain is required.
- Secret-dependent `return` is treated as effect-free (`:28060-28072,
  :28564-28583`). A branch can therefore skip a later public output without
  carrying its secret control dependence to the continuation. Track
  exit-sensitive reachability or emit a blocking typed unknown.
- Enclosing loop/pattern binders are seeded by *name* in the PC scan. A later
  public `let` shadowing that name can be mistaken for a protected binder.
  Pass the visible lexical binding identity and its protection into the
  region instead.
- Ordinary nonescaping branch-local writes and a pure forwarded builtin
  such as `identity(1)` appear to receive blocking implicit-flow diagnostics.
  Preserve acceptance controls as well as invalid twins; track local escape
  and use, and give builtins checked effect summaries.

The separate diagnostics patch statically maps
`ANUBIS_IMPLICIT_FLOW_UNRESOLVED` to a typed, build-blocking undecided result.
That mapping cannot compensate for a missing producer obligation and has not
been tested. The next dependency is a reviewed transfer design with stable
binding identities, complete callable alternatives, definition-time captures,
and exit-aware control flow. Then build the exact candidate in the lead lane,
run the frozen D9 matrix plus matched valid/invalid controls, classify each
verdict and diagnostic flip, and obtain independent review of the actual diff.
An unrelated IFC2 refusal is not proof that this direct producer found a
writer-located implicit-flow obligation.
