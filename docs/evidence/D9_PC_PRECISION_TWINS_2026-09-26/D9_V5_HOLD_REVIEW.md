## Blocking findings

1. **The `for` binder is reintroduced after the legacy precision exclusion.** Both direct and descended `Stmt::For` call sites remove `var` from the legacy root set (`v5-tree/compiler/src/middle/mod.rs:17152-17160`, `:21016-21024`) but pass `PcWriteRegion::Stmts(body)`. The PC collector starts that region with no bound names (`:28229-28234`), records an assignment to the loop-local `i` as an outer target (`:27956-27969`, `:27987-27990`), puts its root back into `written_roots` (`:28241-28245`), and rejects an unprotected pre-loop `i` (`:28252-28274`). Minimal unrun valid oracle: `fn f(s: secret<i64>) { for i in 0..s { i = 0; } } fn main() { f(3); }`. Native lowering creates a mutable per-iteration local (`compiler/src/backends/run.rs:3745-3780`). This program performs no externally visible write or output.

2. **A closure body is judged when a closure is created, despite not being called.** `collect_pc_write_expr` descends every `Expr::Lambda` body (`v5-tree/compiler/src/middle/mod.rs:28109-28112`). A secret guard around `let unused = || { row.n = 1; 0 };` therefore reports a public `row.n` write through `:28241-28274` even if the closure is never invoked. With `row = Row { k: s, n: 0 }`, the former root-only PC rule saw an already-secret root; v5 newly refuses a valid public-field projection after the branch. A call-site PC check or a deferred-effect summary is needed to charge closure writes where execution can occur; traversing the literal as an executed body is not a precision-preserving substitute.

3. **A declared protected branch-local binding is unconditionally called unsafe.** `Stmt::Let` adds its name to `bound` (`:27979-27982`); a later assignment inserts only its spelling into `shadowed` (`:27956-27969`); a global `shadowed.contains(v)` sets `protected=false` (`:28252-28255`), without consulting that local's `secret<T>` declaration. Static oracle: an outer `let x: secret<i64> = s;` and an inner `if s > 0 { let x: secret<i64> = s; x = 1; }` write only protected local storage, but v5 refuses. The old root-only rule accepted this spelling because the pre-branch outer `x` was secret. Independently, global `shadowed` conflates writes to different bindings with the same name across arms; a later outer write inherits the local's refusal. The design needs per-binding/per-target identity, or an explicitly scoped local declaration transfer, not a root-name boolean.

4. **`while let` binder context is not supplied to the direct PC decision.** The candidate collector handles a nested `Stmt::WhileLet` by extending `bound` with pattern names (`:28010-28018`), but direct `Stmt::WhileLet` call sites pass an unseeded `PcWriteRegion::Stmts(body)` (`:16870-16889` and the descended counterpart `:20974-20985`). The pre-binder scope is then used for both destination type and structural shape (`:28182-28210`, `:28229-28265`). A body-local pattern name that shadows an outer Row can be classified using the outer Row's protected-field declaration, or a valid protected local can be refused. This is not a verified executable leak; it is an unresolved identity mismatch that the new place-aware rule must not certify.

5. **The destination sweep charges unreachable nested writes.** `collect_pc_write_stmts` traverses both nested `Stmt::If` bodies without a reachability check (`:27992-27999`); the enclosing PC decision runs before branch analysis (`:16410-16430`). Static oracle: after constructing `row = Row { k: s, n: 0 }`, `if s > 0 { if false { row.n = 1; } } println(row.n);` has no executed public-field write, but the outer secret-PC sweep sees `row.n` and predicts `ANUBIS_IMPLICIT_FLOW`. The former root-only rule accepted this form because `row` was already secret from `k`. A reachable-path distinction or a bounded dead-arm filter is needed, with the discarded branch still checked for ordinary syntax/type errors as required by the language contract.

It does not cover loop binders, nested shadowing, or an uncalled closure.

The sweep recursively visits current expression and statement variants, including conditions, range bounds, scrutinees, guards, value blocks, and container expressions (`:27961-28176`). It tracks only writes rooted in syntactic places and a named in-place builtin set; unknown indirect calls and effects still need typed write summaries. The exact free-function egress summary is opt-in for straight-line bodies and falls back to the older index summary for unsupported forms (`:39564-39731`, `:19083-19111`); this review does not upgrade that fallback into a complete interprocedural guarantee. Declassification and direct field rewriting retain structural shape only in bounded cases; unknown carriers conservatively fall back.
