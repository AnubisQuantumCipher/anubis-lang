## Finite abstraction (and its completeness)

**Domain of `SecurityLabel`.** The production type is:

```rust
enum SecurityLabel {
    Clean,
    Labeled { source: Option<String> },
    Unknown { reason: Option<&'static str> },
}
```

**Abstract-label alphabet (7 elements):**

- `Clean`
- `Labeled(none)`  (`Labeled { source: None }`)
- `Labeled(some:s1)` and `Labeled(some:s2)`
- `Unknown(none)`  (`Unknown { reason: None }`)
- `Unknown(some:r1)` and `Unknown(some:r2)`

**Boolean and source-input alphabets:** `{false, true}` and `{None, Some("s1")}` respectively for
the `from_legacy_taint` input.

**Completeness argument.** None of the six operations reads any character of `source` or `reason`.
Every branch matches on the variant tag and on the `Option` presence bit only. `join` combines
`Option`s with Rust's `Option::or`, a strictly presence-preserving operation whose contents pass
through unread. `to_legacy_taint(Unknown{..})` emits a FIXED constant string (`"unknown-label"`)
regardless of the reason. `from_legacy_taint(false, Some(_))` emits a different FIXED constant
(`"legacy-shape: taint_source without tainted"`) regardless of the source contents. Both constants
are named on both sides as string LITERALS, so there is no shared canonicalization table smuggled
between Rust and Lean — the byte identity of every emitted row comes from the two implementations
independently constructing the same string.

Two representative tokens per position are the MINIMUM needed to expose join's LEFT-BIASED
`Option::or` fallback. A single-token corpus would silently accept full-record commutativity as a
theorem, which is FALSE — the Lean theorems `join_full_not_commutative` and
`join_full_not_commutative_unknown` machine-lock this via a concrete counterexample.
