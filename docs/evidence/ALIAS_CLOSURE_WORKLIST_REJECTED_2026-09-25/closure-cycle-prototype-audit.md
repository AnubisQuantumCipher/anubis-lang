## State and traversal invariant

`ClosureEffectJob` (`mod.rs:16532`) owns a cloned body, mode and complete scope. Parameters have already been bound by the existing application consumer before submission. `ClosureEffectWork` (`16540`) stores complete keys, pending jobs and current logical depth. The scope is never mutated after submission; each job's block walker derives local scope clones as before.

`closure_effect_state_key` (`16554`) serializes `(Mode, Expr, BTreeMap<String, ScopeBinding>)` through derived Debug to a complete string. This is exact equality of the full strings, not a truncated prefix or a digest. The formatter checks `analysis_limit::cut()` on every `write_str`; a partial or interrupted representation never enters `seen`, and the sticky request limit remains set. No cap constant changes.

`analyze_closure_body_effect` (`16581`) installs a worklist only for one synchronous root call. Nested calls submit fresh complete states and return to the current job. The root processes all queued jobs before returning unless the request's existing analysis guard refuses. It does not publish a successful summary or return a source label. A duplicate state means the same body and every same abstract binding under the same frozen semantic context; its output is already scheduled or emitted. A changed argument label, capture, callable alternative, metadata field, or mode creates different text and separate work. This applies equally to body variants with statements: the existing local scope mutation runs inside the job, while inputs from the enclosing scope were captured at submission.

The root keeps `analysis_limit::Frame` tokens corresponding to the logical depth of fresh states. Tokens are resized when changing queued paths. Frames already active outside this root remain owned by their caller. Duplicate state edges add no fresh semantic expansion; all fresh paths still enter the existing depth guard. The native call stack no longer grows solely to rediscover closure-effect states. No early return occurs after the root worklist is installed and before it is cleared. A nested key-format failure returns without destroying the root worklist; the root sees the sticky limit and clears only its own worklist. The frames drop with the root. A panic abort/unwind is not an acceptance path and no cache survives into a new SemanticContext.

The parent must observe whether rv30 actually stabilizes before the guard. Full-state equality is deliberately conservative: unrelated scope differences, capture IDs, or labels that keep growing can prevent reuse. This prototype has not established that rv30 is restored. If state growth persists, it needs source-level precision work, not a larger limit.

## Complete Debug graph and representation check

The equality claim is conditional on the current source graph and standard formatting behavior. Debug is not a generally safe semantic serialization; this audit is why the present graph can be compared. Any future custom Debug implementation, opaque field, mutable capture, or numeric representation change in this graph must trigger review. Replacing this with a designed structural key remains preferable if the prototype earns acceptance.

- `Mode` (`frontend/mod.rs:89`) is a derived-Debug enum.
- `Expr` (`frontend/mod.rs:513`) is a derived-Debug enum. Its edges reach `Expr`, `Stmt`, `Pattern`, `MatchArm`, `Span`, `ForSource`, strings, vectors, boxes, options and pairs. `Stmt` (`444`), `ForSource` (`436`), `MatchArm` (`427`), `Pattern` (`339`), and `Span` (`56`) all derive Debug. Literal numbers and pattern literals are stored as strings. There are no f32/f64 fields, so NaN formatting, signed-zero equality, and decimal rounding cannot collapse stored float bits here.
- `ScopeBinding` (`mod.rs:192`) derives Debug over every field: BindingInfo, closure arity, primary lambda, field/alternative lambdas, preferred alias, complete identities, may names and openness, field identities, builtin tags and field tags, both lattice labels, the legacy secret bit, whole-struct source, complete captures, list/map facts. No field is omitted. `BindingInfo` (`52`) derives Debug including its name, type, mode, taint, source, declassification and span.
- `FnIdentitySet` (`346`), `FnMay` (`408`), `BuiltinGateTag` (`446`), and `BuiltinGateTags` (`458`) all derive Debug. Their maps and sets are BTree collections and carry their complete contents in sorted order.
- `SecurityLabel` (`security_label.rs:75`) derives Debug for Clean, Labeled source and Unknown reason. String and static-string data are escaped and delimited, not concatenated without boundaries.
- `WholeSrc` (`whole.rs:127`) derives Debug over the complete recursive value/computed/holds/record/deep representation.
- `Captures` (`whole.rs:732`) derives Debug over `Rc<Locals>` and optional `Rc<Bound>`. `Locals` is `BTreeMap<String, Local>`; `Local` (`714`) derives Debug for Src (source and Kind), Closure, Named, Opaque and Any. `Bound` (`742`) derives Debug for all functions and certainty. `Closure` (`653`) derives Debug for lambda contents, id, captured environment and use_scope. `Kind` (`671`) derives Debug including list/map/type/sure fields.
- No custom Debug implementation occurs in the above graph. The custom `Local::PartialEq` and `Closure::same` are irrelevant to this text comparison. Rc's Debug traverses the pointee; no Rc address replaces contents. Closure's explicit id is included independently. Sharing that differs while all contents and ids match is semantically interchangeable for these reads.
- No `RefCell`, `Cell`, `Weak`, mutable reference, opaque pointer, or borrowed-placeholder Debug occurs below ScopeBinding/Expr. Rc edges are immutable capture snapshots, made from previous locals by `Env::closure` (`whole.rs:1134`) or prior-scope `closure_captures` (`4203`); the represented capture graph has no mutable cell that could later create a cycle. The explicit closure id comes from the retained Rc lambda address (`1141`), so this key conservatively distinguishes different allocation identities. Its lambda and captures are also included, guarding against mere address reuse.
- `RefCell` occurrences in `whole.rs` belong to query Env caches (`1012`), global pure memo storage (`120`), and Retype caches (`1703`), not Captures. Its floating parsing at `544` computes an integer selector; it is not a field in this key. Frontend f64 occurrences describe type spellings, not stored float values in Expr.

String escaping, enum/struct tags and delimiters, collection delimiters and field labels make the current full derived representation structurally distinguish its values. No manual `format!` summary of only selected fields is used. This is source reasoning for the current compiler representation, not a stable Debug ABI claim.

## SemanticContext read/write boundary

The scope/body key excludes SemanticContext because all semantic input fields remain fixed for the entire synchronous root drain. It does not attempt reuse across root applications, statement analyses, functions, summary fixpoint rounds or check requests. Therefore additional context-read fields do not need a generation hash so long as this mutation boundary is preserved.

The direct effect walker (`mod.rs:16655`) and block walker (`18801`) read free/method function identities, parameter lists, return and application summaries, declared/inferred effects, taint/secret summary sets, user-function precedence, struct/return/enum type information and whole-container shape exclusions. The adjacent `closure-effect-context-fields.txt` records a conservative source scan of their field names and the local-function call graph's field union. `closure-effect-static-calls.txt` records the supporting local call graph; `scan_effect_calls.py` is a lexical aid with comments/strings stripped, not a Rust semantic proof or a substitute for manual review. Module-qualified calls and methods were reviewed separately.

Specifically, local helper reads extend those direct tables with `fn_return_values`, `method_return_values`, `fn_sole_return`, `method_sole_return`, `fn_recursive_container_ids`, `return_feeding`, and `authorized_caps`. `place_types` (`11759`) exposes only shared struct fields, free/method return types and enum payload types. `safe_cap_allowed` (`37772`) only reads authorized_caps. None is updated by an effect job.

Every reachable local free function taking mutable SemanticContext is one of:

- The root scheduler (`16581`), expression walker (`16655`) or block walker (`18801`). Walkers append diagnostics/taint traces/effect tags or mutate local derived scopes. The block walker calls `seed_effect_let`, pattern/alias/whole helpers using shared context. It never invokes analyze_stmts/analyze_function or contract generation.
- `check_applied_callback` (`1942`), `check_applied_callback_targets` (`1966`), `check_forwarded_callbacks` (`2084`), `charge_applied_callback_capabilities` (`2144`): these read target/tag/summary tables, emit ordinary diagnostics/effects and submit further closure jobs.
- `charge_applied_builtin_gate_tags` (`3452`): besides inherited capabilities it sets applied_builtin_leg2/applied_builtin_secret to true (`3466`). These flags are monotone application witnesses, reset at function entry (`7532`) and consumed only after body analysis (`8314`), so pending jobs may contribute them without changing the semantic inputs of another job.
- `reject_implicit_flow_under_secret_pc` (`25829`): emits a diagnostic from supplied labels and assigned roots.
- `apply_inherited_capability` (`37683`): reads authorization/mode, appends effect tags and emits diagnostics.

The SemanticContext methods `emit` and `push_diag` (`4549` onward) read shadow and the sticky limit, and mutate diagnostics, shadow diagnostics and limit_mark only. No later effect computation uses prior diagnostic count/content or prior taint-trace/effect contents as semantic inputs. Effects are appended, not queried to decide later applications. The queue pointer is scheduling state only.

The whole lane receives shared context (`whole::call_egress`, `whole.rs:4183`) and creates a fresh `Env` (`1062`) per query. Its reads additionally include whole_fns, whole_methods, whole_num_formals, whole_builders, whole_part_writers, whole_not_list/map, whole_released, whole_retype and the ordinary declaration/label tables. All non-cache fields remain fixed during the drain. Fresh Env owns work/depth counters and active fixed-point approximations; jobs do not share incomplete Env approximations.

Interior-mutability exceptions are existing memoization, not semantic-context updates:

- `helper_labeled` (`mod.rs:27341`) computes from fixed secret/taint summary sets and return_feeding, then stores the completed table. Its cache stamp is not changed by effect traversal.
- `whole_retype` shared caches (`whole.rs:1740`) cache body/declaration questions. Recursive in-progress sentinels in `memo_sure` (`2248`) and fn_returns_own (`2715`) are conservative false/None and finish synchronously inside the whole query. The worklist is not entered while such a sentinel is borrowed or still being decided.
- `whole_memo` reuse (`whole.rs:8242`) contains portable finished summaries only: insertion (`8347`) is in the branch with no unresolved dependencies and no fallback, with no closure-bound inputs or function-valued output. Query-local active/tentative summaries stay in Env. The worklist does not publish a new summary into this cache.
- Existing return-value memo TLS and analysis-limit TLS remain under their original request lifecycle. An analysis cut is sticky and noted; worklist reuse does not convert its fail-closed output into a successful summary.

This audit preserves the checker assumption that those existing memo routines cache sound answers. It does not independently prove the whole lane, which is larger than this scheduling change. A future effect helper that mutates semantic context or depends on accumulated outputs invalidates the per-root key argument and must be included or isolated before reuse.

## Output and resource consequences

The root computes the union of reachable diagnostics, effect tags and monotone application witnesses. Identical-state duplicate outputs may appear once within a root, and the worklist changes order relative to depth-first recursion. Enforcement of inferred capabilities uses a BTreeSet at `mod.rs:8129`; diagnostic enforcement is presence-based, not occurrence-count-based. Raw effect vectors are still copied to MIR/HIR (`8610`), so evidence serialization/order differences remain observable and require corpus/gate review. No obligation-generation function is reachable from this effect-only call graph; source/contract traversals are unchanged.

Complete-state string retention and job cloning can be expensive. The ordinary memory/stack guard remains active during formatting and analysis, but the existing recursively derived Clone/drop operations are not newly made stackless. The prototype has no performance receipt, no claim that all recursive representations are safe, and no reason to run the known crash on the host. Parent validation must preserve isolation requirements.
