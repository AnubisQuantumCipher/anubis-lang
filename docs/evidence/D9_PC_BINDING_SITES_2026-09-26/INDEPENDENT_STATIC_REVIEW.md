## Patch decision

- The transfer is attached only to Safe `Stmt::If`, before the existing direct diagnostic producer. It preserves `collect_assigned_roots` on each arm and passes the filtered set to the unchanged `reject_implicit_flow_under_secret_pc` at candidate `middle/mod.rs:16211-16229`; the original diagnostic code and message producer remain at candidate `middle/mod.rs:27999-28023`. Other PC producers and IFC2 are outside the patch.
- The new grammar admits only `Stmt::Let` with a closed initializer and `Stmt::Assign` to `Expr::Var` with a closed RHS (`middle/mod.rs:27738-27780`). Every admitted assignment contributes one site to `writes` before filtering. The old collector records every such direct `Expr::Var` target via `assign_target_root` (`middle/mod.rs` base `23179-23187`, `27752-27763`), and the patch requires equality of the old and new distinct-root sets before filtering (`candidate:27807-27820`). Equality alone would lose duplicate sites; the closed grammar and per-assignment `Vec<PcBindingSite>` provide the site coverage here. Any nested statement, call, block expression, field/index target, compound operation expressed outside these AST arms, expression-position assignment, egress, or unknown form returns `Unsupported` and retains the full old set (`candidate:27776-27793`). This is a soundly narrow **precision** transfer relative to the existing direct producer; it does not repair a miss in that producer's own root collection.
- Each arm has its own local-name map. A declaration is installed after its initializer; a write before shadowing resolves to `PreBranch`; repeated `let`s create different `(arm,index)` sites; a write in the sibling arm cannot reuse a then-arm declaration (`candidate:27705-27724`, `27756-27779`). The tests check public inner, pre-shadow, public reshadow, other-arm outer, and two protected arms (`candidate:27880-27928`). The filter removes a root only when **every** recorded write resolves to a protected branch-local site (`candidate:27814-27820`). Its behavior depends on binding structure, not a fixture-name whitelist; the unit test uses different source spellings (`candidate:27861-27877`).
- The permitted read expressions are bare value reads and literals, `!`, comparisons, and Boolean operators over the same grammar (`candidate:27738-27752`). The current native lowering maps local `Expr::Var` to a clone and free names to a closure value without applying it (`backends/run.rs:4552-4640`), comparisons to `anubis_cmp`, and Boolean operators to value conversions (`backends/run.rs:4640-4684`). `anubis_cmp` delegates to built-in value equality/ordering, without user callbacks (`backends/run.rs:1887-1968`). No admitted expression executes an Anubis call, assignment, output, or mutating builtin. Resource exhaustion or divergence of a recursive value comparison is outside this output-flow argument, not evidence of termination.
- The native emitter lowers an `if` arm inside Rust braces, emits `let mut` for the inner declaration, and emits direct variable assignment by name (`backends/run.rs:3593-3623`, `3689-3708`, `5618-5626`). Rust's lexical shadow therefore makes a simple protected inner `let` distinct from the printed outer local. The analyzer snapshots/restores block scope after each arm (`middle/mod.rs:16246-16322`, `9649-9656`). This supports the target positive oracle; it is still a static correspondence argument, not an execution witness.
- Rust shape is plausible: `Stmt::Let` has `name`, `ty`, `init`, `span`; `Stmt::Assign` has `target`, `value`; `Expr::Binary` and `Expr::Unary` have the matched fields (`frontend/mod.rs:486-640`). `Span` implements `Default` (`frontend/mod.rs:55-56`); `Mode` implements `PartialEq` (`frontend/mod.rs:88-89`); the module imports `BTreeMap`, `BTreeSet`, and `Span` (`middle/mod.rs:3-8`). `PcBranchArm` and `PcBindingSite` contain copyable/ordered fields and derive traits needed by the tests (`candidate:27709-27719`). This is a syntax/type plausibility review, not a compiler result.

One existing semantic caveat should be kept visible: the helper described as an anchored secret qualifier delegates to `ty::is_secret`, which currently uses `contains("secret<")` (`middle/ty.rs:470-476`). Thus a hypothetical generic name ending in `secret` can be treated as protected, though the closed arm still has no path to change the outer local or perform output. Do not describe the classifier as a structural type-resolution system or as D9 closure. Its `Unsupported` is internal; the retained old diagnostic is a conservative refusal, not a checked counterexample.
