## Why the narrow removal is justified

The current direct producer builds a BTreeSet of source-name roots from the then and else bodies, then asks whether each root is secret in the **pre-branch** scope (compiler/src/middle/mod.rs:16211-16226 and :27705-27725). Its collector descends through statement branches and expression positions but has no binding identity (compiler/src/middle/mod.rs:27752-27807, :28193-28299). In the registered valid source, the assignment follows a protected inner declaration (fixture :2-7). The runtime emits that declaration as a local Rust let, the assignment as a local rebind, and each if arm in its own braces (compiler/src/backends/run.rs:3593-3601, :3615-3621, :3689-3707). The middle pass also marks an explicitly annotated secret let secret and restores the pre-branch scope after each arm (compiler/src/middle/mod.rs:13941-13945, :14244-14265, :16291-16319, :9641-9654). Thus a direct write proven to resolve to that branch-local protected declaration cannot alter the printed public outer binding. The registered invalid twin has no shadow; its write resolves to the outer binding and must retain the original direct refusal.

Implement this specific transfer as a classifier called on the original borrowed Stmt::If, its current pre-branch scope, and its original arm slices at compiler/src/middle/mod.rs:16211-16225. Give each pre-existing name an Entry origin and each accepted let a structural Inner(arm, statement-index) declaration ID. Walk the then and else arms independently in source order. Check a let initializer in the environment *before* binding its new name; then bind the new ID with the qualifier given by the existing is_secret_type rule (compiler/src/middle/mod.rs:25747-25752). Check every direct assignment against the current arm environment. A fresh ID for each let matters: a later public re-shadow must not inherit an earlier protected ID. No ID needs to be inferred from a name, a span, a pointer, or a branch-merged scope.

Use a **closed grammar** for the first removal: read-only guard; arm statements are only Let with read-only initializer or Assign with Expr::Var target and read-only RHS. Read-only expressions may include Var, Literal, StrLiteral, and explicitly admitted pure Unary/Binary operators with recursively read-only operands. All other Stmt and Expr variants, an unresolved target, and any malformed/opaque form return UnresolvedCoverage and leave the old assigned set untouched. The AST has Call, CallExpr, Index, FieldAccess, Match, If, Block, Lambda, Try, Other and further expression forms (compiler/src/frontend/mod.rs:555-677); the runtime lowers direct calls and operator expressions through different paths (compiler/src/backends/run.rs:4640-4690). Operator admission should be explicit, with no call or deferred application hidden under the word “pure.” Runtime traps or termination behavior are outside this output-flow transfer; read-only here certifies absence of mutation and egress, not total execution.

For a classified if, collect every direct Assign site and its resolved ID, not merely each distinct name. Compare the classifier's distinct-root set to the old collect_assigned_roots result as a release check. Remove an old root only when **all** of its classified assignment sites resolve to protected Inner IDs. The old collector stores only a BTreeSet, so equality of sets alone cannot distinguish two same-name writes on opposite sides of a shadow. The closed grammar makes site coverage provable: a Let initializer, guard, and Assign RHS cannot hide a write; each accepted Assign to Var contributes exactly its target name to the old collector (compiler/src/middle/mod.rs:27755-27768, :28193-28299). If any syntax is outside that grammar, retain the whole original set rather than try to reconcile a lossy per-name count. A total explicit match over the AST variants is preferable to a silent clean wildcard, per repository AGENTS.md's walker-parity rule.

## Concrete failure cases the classifier must refuse to filter

- Write before shadow: in a secret arm, out = 2; let out: secret<i64> = s; out = 3;. The first assignment reaches Entry(out), although the later one reaches a protected Inner ID. The old BTreeSet has only the spelling out; a “some protected write” or set-only test would incorrectly remove it. The registered outer-invalid fixture is the simpler no-shadow negative control (fixture :2-6).
- Sibling-arm binder: if the then arm declares protected out and assigns it, while the else arm assigns out without a declaration, the else assignment reaches Entry(out). Arm environments cannot merge before classification. The runtime emits separate braces for the arms (compiler/src/backends/run.rs:3689-3707).
- Branch-local output: let out = 0; out = 1; println(out); inside a secret arm must not be certified by shadowing. ExprStmt falls outside the closed grammar, so the old direct root refusal remains. The design's public-inner control must contain a real observable output and must require a direct producer diagnostic, not just an IFC2 refusal.
- Expression-position write: a let initializer that contains an if/block expression assigning the outer out, followed by a protected let out and its assignment, must fall back. The old collector descends into those expression bodies (compiler/src/middle/mod.rs:27762-27768, :28193-28225); a statement-only new walker would miss the earlier write.
- Field/index and mutating call: out.n = value, out[i] = value, or push(out, value) can enter the old root set through assign_target_root or the mutating-builtin arm (compiler/src/middle/mod.rs:23177-23185, :27755-27760, :28242-28260). They are outside the direct-Var grammar. A call with no collected root does not test this filter at all; construct unknown-call controls with an accompanying collected root if the intended oracle is “fallback preserves the direct diagnostic.”
- Lambda and aliases: the old expression collector descends into Lambda bodies (compiler/src/middle/mod.rs:28242). A lambda literal may be deferred, and runtime closures capture value snapshots (compiler/src/backends/run.rs:5129-5187); this transfer cannot classify its execution. Likewise, field/callable aliases and value-flow summaries remain outside the certificate. For ordinary collection aliases, runtime values use copy-on-write on shared payloads (compiler/src/backends/run.rs:1453-1462, :1752-1756), but that observation does not license accepting an unknown call or place write.

The public-field gap remains: assign_target_root reduces a field place to its root, while reject_implicit_flow_under_secret_pc skips a root marked secret (compiler/src/middle/mod.rs:23177-23185, :27715-27725). A secret Row with a public n field written under secret PC may have **no old direct refusal to preserve**. This classifier cannot repair it; do not infer field safety from a protected root or count a generic/IFC2 refusal as the missing direct writer finding. This is also the boundary recorded in docs/evidence/D9_PC_PRECISION_TWINS_2026-09-26/README.md:34-51.

## Pointer bridge versus direct collection

The pointer bridge can be made fail-closed if it is request-local, maps the exact live AST, rejects missing or duplicate paths in release, and never treats a cloned statement's absent pointer as an identity. It is unnecessary for this producer. The current Stmt::If arm already has borrowed branch slices and the pre-branch scope in one call (compiler/src/middle/mod.rs:16211-16225), while the held patch only creates a whole-function inventory checked by debug_assert! at binding-sites-v2.patch:11-23. The source also constructs cloned/renamed statements elsewhere (compiler/src/middle/mod.rs:11541-11585), and there is a second direct-PC statement-if path for descended closure bodies (compiler/src/middle/mod.rs:20654-20669). A global pointer bridge would have to specify which of these AST instances it covers and maintain source paths through additional walkers. An Entry/Inner origin map constructed directly from the original arms avoids that mapping obligation for the first consumer. It remains a structural lexical identity within this if, not a general D9 BindingId for fields, calls, closures, or branch continuation.
